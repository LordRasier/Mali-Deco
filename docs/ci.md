# Integración continua

El workflow de GitHub Actions se ejecuta en solicitudes de cambios (`pull_request`) o manualmente; no despliega ni usa secretos del repositorio. Instala dependencias desde el lockfile sin scripts de ciclo de vida ni auditoría, y ejecuta lint, comprobación de tipos, pruebas web/API y build de producción con Node 24. La disponibilidad y el resultado deben comprobarse en la ejecución de Actions; la existencia del workflow no significa que haya pasado.

La prueba de integración usa un servicio desechable de la imagen oficial MySQL 8.4, con la base exclusiva vacía `store_integration_test` y credenciales ficticias de CI. Aplica las cuatro migraciones, comprueba restricciones y operaciones seleccionadas del catálogo e identidad (incluida la sesión), y las revierte. Si falla puede dejar tablas en ese servicio, que se elimina con el job; no apunta a ninguna base del usuario. No es una prueba integral de todo el negocio ni valida pagos, envíos, integraciones externas o una puesta en producción. Crea un usuario de prueba temporal; no crea una cuenta productiva ni persistente. Para pruebas locales, seguir las precauciones del README y usar únicamente una base aislada y vacía.

# Cotización Zipnova: base desconectada

Este corte agrega un adaptador de opciones múltiples, un resolver de catálogo y la ruta `POST /api/v1/shipping/quote`. La ruta valida datos pero permanece bloqueada y devuelve `DISABLED` antes de consultar catálogo o red. Las pruebas usan transporte ficticio. La implementación existente de Andreani no cambia.

El adaptador recibe identificadores, cantidades y destino; un resolver inyectado debe consultar precios, productos y embalaje del servidor. Sin catálogo o datos logísticos devuelve indisponibilidad antes de invocar el transporte. El usuario indicó que agrupa los artículos: `items` con `type_packaging=dynamic` envía una entrada por cada unidad comprada, para que Zipnova agrupe según la configuración de la cuenta. No se usa cada unidad como bulto ni se inventa una caja. También se admite la alternativa de bultos previamente resueltos.

Se usa `account_id` y `origin_id` explícitos. Peso en gramos y medidas en centímetros enteros: para `items` los milímetros se redondean hacia arriba al siguiente centímetro, sin subdeclarar ni añadir otro margen; para bultos ya definidos se exige conversión exacta. No se redondean pesos inferiores al mínimo permitido. El valor declarado usa precisión monetaria configurada y, al enviarse como número JSON, se rechaza si alcanza `10^(15-exponente)` o si el catálogo detecta pérdida de precisión. Se toma `amounts.price_incl_tax` del comprador conservando el texto numérico original de JSON antes de su conversión a unidades menores, sin sumar IVA ni multiplicar por bultos; moneda configurada explícitamente. Se ignoran resultados no seleccionables y puntos de retiro ausentes; para retiro se conserva `point_id`. En modo dinámico se valida y conserva el número de bultos devueltos por Zipnova. La opción seleccionada se suma con enteros exactos al subtotal solo si todo está en la misma moneda; se invalida ante cambios de carrito, precio o destino. El adaptador distingue fallos de configuración, catálogo, logística, destino, autorización, límite, timeout, respuesta y ausencia de opciones.

La cuenta tiene seleccionado empaquetado dinámico con límite de lado 150 cm y peso 30.000 g. Zipnova intenta minimizar bultos, pero puede generar más de uno. La guía no confirma cómo añade protección o tara de la caja; no se agregan valores inventados. Debe acordarse y verificarse qué protección está incluida en las medidas cargadas para cada unidad y contrastar bultos calculados con pedidos físicamente embalados. La API no documenta moneda en la respuesta de cotización. No hay sandbox confirmado. No se probó tarifa real, ni se creó o pagó envío. Antes de activar: validar catálogo y precios con la base de datos elegida, logística, moneda, origen, credenciales y permisos; conectar el flujo y probarlo. No incluir credenciales en archivos versionados, logs o cliente.

## Transporte y futura entrada local

`createZipnovaTransport` devuelve `undefined` salvo `ZIPNOVA_ENABLED=true`. Aun activado, solo construye una función para el endpoint fijo de cotización; nunca crea envíos. El servicio Nest conserva un bloqueo adicional no configurable que impide llamarlo, aunque existan credenciales. Rechaza redirecciones, establece timeout y limita respuestas. Las pruebas usan exclusivamente `fetch` simulado. El código recibe `ZIPNOVA_API_TOKEN` y `ZIPNOVA_API_SECRET` mediante el entorno del proceso, sin imprimirlos.

Para una futura configuración local, el usuario puede ejecutar desde la raíz del proyecto `powershell.exe -NoProfile -File .\scripts\setup-zipnova-local.ps1` en su propia consola. El script solicita token y secret con entrada oculta, crea `%LOCALAPPDATA%\MaliDeco-Zipnova\zipnova.env` fuera del repositorio, restringe la carpeta al usuario de Windows y deja `ZIPNOVA_ENABLED=false`. No sobrescribe una carpeta existente ni acepta credenciales en argumentos. El archivo guarda texto sin cifrar y requiere proteger la cuenta y sus respaldos; no debe copiarse al chat, repositorio o almacenamiento sincronizado. El script admite solo caracteres seguros para el formato; se probó en una carpeta temporal con valores ficticios, nunca con credenciales reales. Node 24 puede cargarlo con `node --env-file="$env:LOCALAPPDATA\MaliDeco-Zipnova\zipnova.env" apps/api/dist/main.js` desde PowerShell, sin valores en argumentos. Todavía faltan IDs de cuenta/origen, moneda y exponente configurados, validar logística y revisar la activación; el bloqueo adicional sigue impidiendo consultas.

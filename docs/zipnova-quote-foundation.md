# Cotización Zipnova: base desconectada

Este corte agrega un adaptador de opciones múltiples, un contrato para resolver datos confiables de catálogo y embalaje, y pruebas con transporte ficticio. No registra una ruta, transporte de red ni credenciales. El proveedor deshabilitado devuelve `DISABLED`. La implementación existente de Andreani no cambia.

El adaptador recibe identificadores, cantidades y destino; un resolver inyectado debe consultar precios, productos y embalaje del servidor. Sin catálogo o datos logísticos devuelve indisponibilidad antes de invocar el transporte. El usuario indicó que agrupa los artículos: `items` con `type_packaging=dynamic` envía una entrada por cada unidad comprada, para que Zipnova agrupe según la configuración de la cuenta. No se usa cada unidad como bulto ni se inventa una caja. También se admite la alternativa de bultos previamente resueltos.

Se usa `account_id` y `origin_id` explícitos. Peso en gramos y medidas en centímetros enteros: para `items` los milímetros se redondean hacia arriba al siguiente centímetro, sin subdeclarar ni añadir otro margen; para bultos ya definidos se exige conversión exacta. No se redondean pesos inferiores al mínimo permitido. El valor declarado usa precisión monetaria configurada. Se toma `amounts.price_incl_tax` del comprador, sin sumar IVA ni multiplicar por cantidad de bultos; la moneda debe configurarse explícitamente. Se ignoran resultados no seleccionables y puntos de retiro ausentes; para retiro se conserva `point_id`. En modo dinámico se valida y conserva el número de bultos devueltos por Zipnova. El adaptador separa fallos de configuración, catálogo, logística, destino, autorización, límite, timeout, respuesta y ausencia de opciones. `QuoteSession` invalida el resultado cuando cambia el carrito o destino y descarta respuestas anteriores; debe integrarse con la interfaz al conectar el flujo.

La cuenta tiene seleccionado empaquetado dinámico con límite de lado 150 cm y peso 30.000 g. Zipnova intenta minimizar bultos, pero puede generar más de uno. La guía no confirma cómo añade protección o tara de la caja; no se agregan valores inventados. Debe acordarse y verificarse qué protección está incluida en las medidas cargadas para cada unidad y contrastar bultos calculados con pedidos físicamente embalados. La API no documenta moneda en la respuesta de cotización. No hay sandbox confirmado. No se probó tarifa real, ni se creó o pagó envío. Antes de activar: validar catálogo y precios con la base de datos elegida, logística, moneda, origen, credenciales y permisos; conectar el flujo y probarlo. No incluir credenciales en archivos versionados, logs o cliente.

## Transporte y futura entrada local

`createZipnovaTransport` no está registrado en Nest y devuelve `undefined` salvo `ZIPNOVA_ENABLED=true`. Aun activado, solo construye una función para el endpoint fijo de cotización; nunca crea envíos. Rechaza redirecciones, establece timeout y limita respuestas. Las pruebas usan exclusivamente `fetch` simulado. El código recibe `ZIPNOVA_API_TOKEN` y `ZIPNOVA_API_SECRET` mediante el entorno del proceso, sin imprimirlos.

Para una futura configuración local, el usuario podrá guardar esas dos variables en `.env.zipnova.local`, archivo ignorado por Git; debe restringir su acceso en Windows a su usuario y no guardarlo en carpetas sincronizadas, logs ni chat. Node 24 permite cargar un archivo con `node --env-file=.env.zipnova.local ...`, sin poner valores en la línea de comandos. Este corte no crea el archivo ni conecta el transporte al servidor: no pedir ni ingresar valores hasta que el flujo, el catálogo y la logística estén listos y revisados. `ZIPNOVA_ENABLED` debe quedar ausente o `false` hasta entonces.

Fuentes: [Cotizar envíos, API Zipnova](https://docs.zipnova.com/envios/recursos-api/envios/cotizar-envios), [configurar empaquetado](https://ayuda-envios.zipnova.com/hc/es-419/articles/47233549333011-Configurar-empaquetado-de-env%C3%ADos), [autenticación](https://docs.zipnova.com/envios/principios/urls-y-autenticacion) y [opción env-file de Node](https://nodejs.org/api/cli.html#--env-filefile).

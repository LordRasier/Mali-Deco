# Retained product administration

[product-dom](product-dom.ts) binds server forms and preserves their native values while the workspace hides the section. [product-controller](product-controller.ts) owns only read/write sequencing, navigation and result handling; it does not duplicate server validation or authorization. [product-runtime](product-runtime.ts) reads fixed server partials. Product validation and category omission-versus-null semantics come from the existing validator through [product-form](product-form.ts).

## Invariants

- Explicit reads supersede older reads; changing sections does not dispose the product owner. Cleanup/authentication epoch changes reject late read and write results. Synchronous cleanup during busy publication cannot start a request or render a committed result.
- Create/update/archive use the unchanged same-origin JSON API with CSRF. Writes are single-flight and never automatically retried. Unknown outcomes preserve the form and warning; an explicit read retry cannot replay a write.
- A confirmed write removes the old editor before loading the saved detail. If that GET fails, only reading the result is retryable, avoiding a duplicate create from the old form. Update acknowledgements must match the edited ID; archive requires explicit confirmation and the canonical empty acknowledgement.
- Creation may include an initial ARS price and supply mode. The dedicated create-with-price endpoint commits the draft and its standard variant in one database transaction; photos remain a separate retained upload queue. An empty price still permits an incomplete draft. Uncertain write outcomes are never automatically replayed.
- List page/search/status/sort survive detail/create/edit navigation and pagination. Applying filters returns to page one; clearing them also resets the search and sort. Cancel from edit returns to detail; cancel from create returns to the remembered list. Archived detail has no edit/archive controls.
- [Quick edits](product-quick-edit.ts) retain each expanded product's drafts. They load 24 variants at a time through the guarded detail API and save a variant's price/inventory together through `PUT /admin/catalog/products/:id/variants/:variantId/quick-adjustment`. The transaction locks parent then variant, compares the displayed price/currency/supply mode and changed stock, and never writes untouched inventory. Made-to-order variants expose price only. A matching acknowledgement clears only that variant's draft and refreshes the parent summary in place. Conflicts and uncertain writes require an explicit value refresh before another save; no write is retried automatically. List navigation warns before discarding pending quick edits.
- [Category options](product-categories.ts) refresh in place through [the shared loader](../taxonomy-options.ts): 100-item pages, at most 1,000 options, stable totals, no duplicate IDs or partial snapshots. Refresh/failure preserves the current selection and draft. A disabled selector's value remains readable, so unchanged assignments are omitted rather than accidentally cleared.
- Product and variant writes share the parent mutation lease: starting either invalidates pending reads and blocks navigation until the outcome settles. Late cancel/detail responses cannot dispose a pending editor or erase its uncertain-outcome warning.
- [Variant writes](variant-editor.ts) retain the same parent, validate acknowledgement identity/types, require explicit supply mode and reuse exact currency conversion through [variant-form](variant-form.ts). Material/color selectors share [native option refresh](../taxonomy-select.ts); omission preserves an assignment and explicit null clears it. Detail, edit, mutation and cancellation retain the selected 24-row variant page.
- [Media ownership](product-media.ts) preserves the exact slot node, file input and upload-intent owner across same-product reads, including variant changes. Product archive makes the child read-only immediately after its acknowledgement; a later stale false cannot re-enable it. Different product, list/create or session cleanup disposes the child. Product busy state does not overwrite media's own disabled/revision state.

The feature uses the existing administrative stylesheet, visible labels, progress/error notices and focusable headings. Browser parity remains a separate gate; controlled DOM doubles are not browser evidence.
